# Audit dataset

Goal: for each L2BEAT-tracked project and for widely reused code, collect the public audit reports, extract exactly which source files and revisions were audited, and fetch those audited sources. The dataset records audit evidence only. 

Comparing it with the code deployed onchain happens in the l2beat monorepo (`packages/audit-diff`), which reads discovery output there and the evidence here.

## Repository structure

- `<project>/` (e.g. `tornado-cash/`, `scroll/`, `unichain/`): one collection per project, containing:
  - `reports/`: original audit reports (PDF) and their Markdown conversions; `reports/irrelevant/` holds reports out of scope for onchain/zk code.
  - `audit-summary.json`: machine-readable extraction of every report: relevance, audited repositories, paths, revisions with their GitHub committer timestamps, and major findings. Repository ids are canonical (`owner/repo` for GitHub), see `normalize.py`.
  - `audit-summary.md`: human-readable rendering of `audit-summary.json`.
  - `audited-sources/`: source files fetched at the exact audited commits, laid out as `<owner>/<repo>/<path>/<commit>/...`, with a `manifest.json` listing fetched and skipped entries. Each fetched file carries `units` (the top-level Solidity declarations it contains, or its basename for other files) and `sha256` of the file as stored after formatting; `git_object` is the upstream provenance.
- `_libs/<vendor>/`: collections for widely reused code (OpenZeppelin, Safe, Solady, Solmate, SP1, ...). Same layout and scripts as a project collection; the grouping is organizational only. See `_libs/README.md`.
- `repositories.json`: registry of every repository referenced by any collection: URL and, for forks, the canonical id of the upstream repository under `fork_of`. Generated by `update_repositories.py`; entries with `"manual": true` are kept across regenerations.
- `foundry.toml`: the forge fmt configuration used for every Solidity file in the dataset, exported by `format_sources.py` so consumers can format deployed sources identically.
- `AUDIT_EXTRACT_SKILL.md`: instructions for the agent that classifies reports and produces `audit-summary.json`.

## Pipeline

1. `python3 -m venv .venv` and `.venv/bin/pip3 install pymupdf4llm==1.28.2`: set up the local virtual environment and install the PDF extraction dependency.
2. `.venv/bin/python3 pdf_to_md.py`: extract every PDF under the project directories to Markdown.
3. Run an agent on `AUDIT_EXTRACT_SKILL.md` for a project to classify all Markdown reports found recursively under `<project>/reports` and extract `<project>/audit-summary.json`. Irrelevant reports are moved to `<project>/reports/irrelevant`, retained in the summary with a short description, and excluded from detailed source extraction.
4. `python3 pipeline.py <project>`: runs the remaining steps in order. They can also be run individually:
   - `python3 generate_audit_summary.py <project>/audit-summary.json`: validates the schema and canonical repository ids and generates `<project>/audit-summary.md`. Human review of the Markdown is recommended.
   - `python3 fetch_audited_sources.py <project>/audit-summary.json`: fetches every source path from relevant reports that is pinned to a full Git commit into `<project>/audited-sources`. Mutable revisions such as branches and abbreviated commits are recorded as skipped in `manifest.json`. Relative symlinks that stay within the repository are resolved from that same pinned commit and copied as regular files.
   - `python3 format_sources.py <project>` or `--all`: reformats every Solidity file under `audited-sources` with the shared forge fmt config and exports that config to `foundry.toml`. Requires Foundry.
   - `python3 index_sources.py <project>` or `--all`: fills `units` and the post-format `sha256` of every fetched file in `manifest.json` and verifies that every referenced file exists.
   - `python3 update_repositories.py`: rebuilds `repositories.json` from every collection, asking GitHub for fork lineage (requires the authenticated `gh` CLI; `--no-lookup` keeps previously known lineage).

`python3 normalize.py <url>` prints the canonical id for a repository URL. `python3 normalize.py --migrate <collection>` or `--all` rewrites ids in existing summaries and manifests and moves fetched sources to the canonical directories; `--check` reports non-canonical ids without changing anything.
